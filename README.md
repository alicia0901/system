# 飲食店 予約システム

Google Apps Script (GAS) だけで完結する、飲食店向けの予約システムです。

- 予約フォーム(HTML)をお客様向け Web ページとして公開
- 送信内容を Google スプレッドシートに自動記録し、Google カレンダーにも自動登録
- **座席数ベースの空席管理**: 総座席数を基準に、時間帯ごとの空席をコース滞在時間から自動計算(1テーブル専有ではなく複数組の同時予約に対応)
- **店舗側の管理画面**(パスワード保護): 日付ごとの予約一覧の確認・予約の変更(満席の時間帯への変更も強制変更で可能)・キャンセル・電話予約の手動登録
- **満席時のキャンセル待ち登録**: 満席の時間帯でもお客様がキャンセル待ちとして登録可能。管理画面から空席が出た予約を確定に繰り上げできる
- **予約確認メールの自動送信**: お客様へ確認メール、店舗へも新規予約の通知メール(任意)
- **簡易的な連投・スパム対策**: 同じ電話番号からの短時間の連続送信や、短時間の大量送信をブロック
- 営業時間外・定休日・満席の予約は自動的に拒否
- **LINEアプリ内での予約(任意設定)**: LINE公式アカウントの「予約する」ボタンなどから、LINEアプリを閉じずに予約フォームを開ける(LIFF)。詳細は「[LINEアプリ内で予約を受け付けたい場合(LIFF)](#lineアプリ内で予約を受け付けたい場合liff)」を参照

外部サーバは不要です。Google アカウントがあればそのまま使えます。

## ファイル構成

```
飲食店予約システム/
├── README.md
├── gas/                          … 共通エンジン(1店舗目 兼 テンプレート本体)
│   ├── Code.gs                   … サーバ側ロジック(設定・予約処理・空席計算・管理画面API)
│   ├── index.html                … お客様向け予約フォーム
│   ├── admin.html                … 店舗スタッフ向け管理画面(?page=admin)
│   ├── appsscript.json           … GASマニフェスト
│   └── .claspignore
├── setup/                        … 他店舗展開用のジェネレーター
│   ├── create-store.js           … 新しい店舗のコード生成 + 自動デプロイ
│   └── store-config.example.json … 店舗設定ファイルのサンプル
└── stores/                       … create-store.js の生成先(店舗ごとに1フォルダ)
    └── <storeSlug>/gas/
```

`gas/Code.gs` は「共通エンジン + 設定(`CONFIG`)」という構造になっています。新しい店舗を作る際は `CONFIG` ブロックだけを差し替えれば良く、予約ロジック本体(空席計算・営業時間チェックなど)は1箇所のまま共有されます。

## セットアップ手順

### 1. スプレッドシートを新規作成

1. Google スプレッドシートで新しいシートを作成します(タイトルは何でもOK。例:「〇〇食堂 予約管理」)。
2. メニューの **拡張機能 → Apps Script** を開きます。

### 2. コードを貼り付け

1. Apps Script エディタで、デフォルトで作られている `コード.gs`(または `Code.gs`)の中身を全部削除し、この [Code.gs](gas/Code.gs) の内容を貼り付けます。
2. エディタ左側の「+」→「HTML」でファイルを追加し、ファイル名を **`index`** にします(拡張子は付けない)。作成された `index.html` の中身を全部削除し、この [index.html](gas/index.html) の内容を貼り付けます。
3. 同様に「+」→「HTML」でもう1つファイルを追加し、ファイル名を **`admin`** にします。中身をこの [admin.html](gas/admin.html) の内容に置き換えます。
4. 保存します(Ctrl+S)。

### 3. 設定を調整(`Code.gs` 冒頭の `CONFIG`)

```js
const CONFIG = {
  STORE_NAME: '飲食店',           // フォーム・管理画面に表示する店名
  CALENDAR_ID: 'primary',        // 予定を入れたいカレンダーのID
  SHEET_NAME: '予約一覧',         // 記録先シート名(なければ自動作成)
  BUSINESS_START_HOUR: 11,       // 営業開始時刻
  BUSINESS_END_HOUR: 22,         // 営業終了時刻
  CLOSED_WEEKDAYS: [1],          // 定休日(0=日,1=月,…6=土)
  SLOT_MINUTES: 30,              // 予約受付の時間刻み
  MAX_DAYS_AHEAD: 60,            // 何日先まで予約を受け付けるか
  SEATS_TOTAL: 20,               // 総座席数(空席管理の基準)
  PARTY_SIZE_MAX: 8,             // 1回のご予約で受け付ける最大人数
  COURSES: [                     // コースの初期値(★管理画面の「コースの設定」で変更した後は
    { name: 'ディナーコース', duration: 120 },  //   そちらが優先され、ここを書き換えても反映されない。
    { name: 'ランチ', duration: 60 },           //   元に戻すときは管理画面の「初期設定に戻す」を使う)
    { name: 'お食事のみ(コース注文なし)', duration: 90 },
  ],
  NOTIFY_EMAIL: '',              // 新規予約の通知を受け取る店舗側メール(空なら送らない)
  ADMIN_PASSWORD: 'changeme',    // 管理画面のログインパスワード ★必ず変更してください
  WAITLIST_ENABLED: true,        // 満席の時間帯でもキャンセル待ち登録を受け付けるか
  LIFF_ID: '',                   // LINEアプリ内で予約フォームを開く場合のLIFF ID(空なら無効。下記参照)
  RATE_LIMIT: {                  // 簡易的な連投・スパム対策
    MIN_INTERVAL_SEC_PER_PHONE: 30, // 同じ電話番号からの連続送信を制限する間隔(秒)
    MAX_SUBMISSIONS_PER_WINDOW: 20, // 下記ウィンドウ(秒)内で許可する送信数の上限
    WINDOW_SEC: 60,
  },
};
```

- **座席数について**: `SEATS_TOTAL` は「同時にご案内できる総座席数」です。予約はコースの `duration`(滞在時間)の分だけこの座席数を占有するとみなし、時間帯ごとに合計人数を計算して空席を判定します(テーブル単位の割り当てまでは行わない、シンプルな座席数ベースの管理です)。
- **店舗専用のカレンダーを使いたい場合**: Google カレンダーで新しいカレンダーを作成し、そのカレンダーの「設定」→「カレンダーの統合」に表示される **カレンダーID**(`xxxxx@group.calendar.google.com` の形式)を `CALENDAR_ID` に設定してください。
- **管理画面パスワード**: `ADMIN_PASSWORD` は初期値の `changeme` のままにしないでください。管理画面(`?page=admin`)は誰でもURLを知っていればアクセスできる公開ページのため、このパスワードだけが保護になります。

### 4. ウェブアプリとして公開

1. エディタ右上の **デプロイ → 新しいデプロイ** をクリック。
2. 種類の選択(歯車アイコン)で **ウェブアプリ** を選択。
3. 設定:
   - 実行するユーザー: **自分**
   - アクセスできるユーザー: **全員**(お客様が誰でもアクセスできるようにする場合)
4. **デプロイ** をクリックし、権限の承認(自分のGoogleアカウントで許可)を行います。
5. 発行された **ウェブアプリのURL** が予約フォームのURLです。これをお客様に共有したり、お店のホームページにリンク/埋め込みしてください。
6. 同じURLの末尾に `?page=admin` を付けたもの(例: `https://script.google.com/macros/s/xxxx/exec?page=admin`)が **管理画面のURL** です。店舗スタッフだけに共有してください。

> コードを更新したときは、同じ「デプロイを管理」画面から新しいバージョンとして再デプロイしてください(URLは変わりません)。

### 5. 動作確認

1. 予約フォームのURLを開き、テストで1件予約してみてください。
2. スプレッドシートに新しい行が追加されること、カレンダーに予定が入ること、確認メール(メールアドレスを入力した場合)が届くことを確認します。
3. 管理画面URL(`?page=admin`)を開き、設定したパスワードでログインして、今作った予約が表示されること・キャンセルできることを確認してください。
4. 同じ時間帯に座席数を超える人数で予約しようとすると、その時間が選択できなくなる(または送信時に「満席です」と拒否される)ことを確認してください。

## LINEアプリ内で予約を受け付けたい場合(LIFF)

LINE公式アカウントの「予約する」ボタンなどから、LINEアプリを閉じずに今の予約フォームをそのまま開けるようにできます(LIFFという仕組みを使います)。**この設定は任意です**。設定しなくても、通常のブラウザ予約フォームは今まで通り使えます。

### 必要なもの

- LINE公式アカウント(お店の公式LINEアカウント。まだなければ [LINE Official Account Manager](https://www.linebiz.com/jp/entry/) から無料で開設できます)
- 上記アカウントに紐づく Messaging API チャネル(LINE公式アカウントの管理画面の「設定」→「Messaging API」から有効化できます)

これらはLINE側の設定のため、このシステムのコードからは行えません。以下はLINE Developersコンソール上での作業です。

### 手順

1. [LINE Developers コンソール](https://developers.line.biz/) に、LINE公式アカウントと同じLINEアカウントでログインします。
2. 対象のプロバイダー → お店の公式アカウントに対応する Messaging API チャネルを開きます。
3. 「LIFF」タブ → **追加** をクリックし、次のように設定します。
   - LIFFアプリ名: 任意(例: 予約フォーム)
   - サイズ: **Full** を推奨(フォーム全体が見やすくなります)
   - エンドポイントURL: このシステムの予約フォームURL(`https://script.google.com/macros/s/xxxx/exec`。`?page=admin` は付けないこと)
   - Scope: `profile` にチェック(お名前の自動入力に使用)。予約完了時にトーク画面へメッセージを送りたい場合は `chat_message.write` にもチェック
   - ボットリンク機能: 「On(Aggressive)」推奨(フォームを開いたときに自動で友だち追加される)
4. 追加すると **LIFF ID**(`1234567890-AbCdEfGh` のような形式)が発行されるのでコピーします。
5. `Code.gs` の `CONFIG.LIFF_ID` にこのIDを設定し、保存・再デプロイします(他店舗展開している場合は、その店舗の `store-config.json` に `"liffId": "..."` を追加して `create-store.js` を再実行 →`clasp push`)。
6. LINE公式アカウント管理画面の「リッチメニュー」やあいさつメッセージのボタンに、リンク先として `https://liff.line.me/{手順4のLIFF ID}` を設定します。
7. スマートフォンのLINEアプリでお店の公式アカウントを友だち追加し、設定したボタンをタップして、予約フォームがLINEアプリ内にそのまま開くことを確認してください。

### 補足

- `CONFIG.LIFF_ID` が空文字のまま(既定値)の店舗には一切影響しません。通常のブラウザ予約フォームとして今まで通り動作します。
- LINE経由の予約は、管理画面の予約一覧でお名前の横に緑色の **LINE** バッジが表示されます。スプレッドシートにも「申込経路」「LINE表示名」の列が自動で追加されます(既存のシートにも次回アクセス時にヘッダーだけ自動で追加されます)。
- 予約確定後、LINEアプリ内で開いていれば確認メッセージをトーク画面に送信し(`chat_message.write` スコープが必要。未設定でも予約自体は成立します)、「LINEのトーク画面に戻る」ボタンを表示します。

## 予約の流れ(仕組み)

1. お客様が日付・人数・コースを選ぶと、その日のスプレッドシート上の確定予約を参照し、時間帯ごとに「予約済み人数の合計」を計算、`SEATS_TOTAL` を超える時間帯は満席として扱われます(`WAITLIST_ENABLED` が有効な場合は選択自体はでき、「(待)」表示のキャンセル待ち枠になります)。
2. 送信すると `Code.gs` の `submitBooking()` が以下を順にチェックします。
   - 短時間の大量送信・同一電話番号からの連続送信でないか(簡易フラッド対策、`RATE_LIMIT`)
   - 必須項目・人数の範囲(`PARTY_SIZE_MAX` 以内)
   - 過去日時ではないか / 予約可能期間内か
   - 定休日でないか
   - コースの滞在時間を含めて営業時間内か
   - その時間帯の予約合計人数 + 今回の人数 が `SEATS_TOTAL` を超えないか(満席チェック)
3. 満席でなければ、その場でカレンダーに予定を作成し、スプレッドシートに「予約確定」で1行追記し、確認メールを送信します。満席かつお客様がキャンセル待ちを希望した場合は、カレンダー登録は行わずに「キャンセル待ち」ステータスで1行追記し、その旨のメールを送ります。
4. 管理画面では、選択した日付の予約一覧・予約済み座席数・キャンセル待ち件数のサマリーを表示します。
   - **キャンセル**: ステータスを更新し、カレンダーの予定があれば削除します(キャンセル待ちの予約にも使えます)。
   - **編集**(`updateReservationAdmin()`): お名前・電話番号・日付・時間・人数・コース・ご要望を変更できます(ステータスは変更しません)。空席チェックは変更対象自身の現在の枠を除外した上で行うため、同じ時間帯のまま人数だけ変える等でも誤って満席判定にはなりません。「強制変更」にチェックすると定休日・営業時間外・満席チェックを無視して変更できるため、満席の時間帯へ移したい場合はこれを使います。確定済み予約はカレンダーの予定も日時・内容を追随して更新します(キャンセル待ちのままの編集はカレンダー未登録のまま)。
   - **繰り上げ確定**(`promoteWaitlistAdmin()`): キャンセル待ちの予約について、その時点の空席状況を確認した上でカレンダー登録・ステータス更新・確定メール送信を行います。
   - **＋ 電話予約を追加**(`createReservationAdmin()`): 電話等、システム外で受けた予約をその場で登録します。メールアドレスは任意。「強制登録」にチェックすると定休日・営業時間外・満席チェックを無視して登録できます(例外対応用)。
   - **コースの設定**(`getCoursesForAdmin()` / `updateCoursesAdmin()` / `resetCoursesAdmin()`): 予約フォーム・電話予約で選べるコース(名前・滞在時間)を管理画面から追加・編集・削除できます。変更内容は `PropertiesService`(スクリプトプロパティ)に保存され、`Code.gs` の `CONFIG.COURSES`(店舗設定の初期値)には影響しません。そのため、共通エンジンの更新や `create-store.js` による再生成を行っても、管理画面から設定したコース内容は失われません。「初期設定に戻す」でいつでも `CONFIG.COURSES` の内容に戻せます。

## よくあるカスタマイズ

| やりたいこと | 変更箇所 |
|---|---|
| コースを増やす・変える | `Code.gs` の `CONFIG.COURSES` |
| 総座席数を変える | `CONFIG.SEATS_TOTAL` |
| 1回の予約の最大人数を変える | `CONFIG.PARTY_SIZE_MAX` |
| 営業時間を変える | `CONFIG.BUSINESS_START_HOUR` / `BUSINESS_END_HOUR` |
| 定休日を変える | `CONFIG.CLOSED_WEEKDAYS` |
| 予約のデザインを変える | `index.html` / `admin.html` の `<style>` 内 |
| 店舗側にも予約通知メールを送りたい | `CONFIG.NOTIFY_EMAIL` に店舗メールを設定 |
| キャンセル待ちを受け付けたくない | `CONFIG.WAITLIST_ENABLED` を `false` に |
| 連投対策の間隔・上限を変える | `CONFIG.RATE_LIMIT` |
| LINEアプリ内で予約できるようにしたい | `CONFIG.LIFF_ID`(「[LINEアプリ内で予約を受け付けたい場合(LIFF)](#lineアプリ内で予約を受け付けたい場合liff)」参照) |

## 制約・注意点

- **テーブル/座席の個別管理は行いません**。総座席数だけを基準にした空席計算のため、「4人テーブルが3卓、2人テーブルが2卓」のような席割り最適化はできません。席種を厳密に分けたい場合は、コースごとに `SEATS_TOTAL` 相当の枠を分ける等の追加実装が必要です。
- **管理画面のパスワードは単純な共有パスワード方式**です。店舗ごとに強固なパスワードを設定し、URLとパスワードの共有範囲に注意してください。より強固にしたい場合は、Web アプリのアクセス設定を「Google Workspace 組織内のみ」等に変更する方法もあります。
- 確認メールの送信には `MailApp` を使用しており、Googleアカウントの1日あたりの送信上限(無料Gmailアカウントで1日100通程度)に依存します。大量送信が見込まれる場合は上限にご注意ください。

## 他店舗への展開

系列の別店舗や、他の飲食店向けにこのシステムをそのまま複製できます。店舗ごとに **別々の Google スプレッドシート・別々の Apps Script プロジェクト・別々のウェブアプリURL** が発行され、データも完全に分離されます(共有カレンダーやシートはありません)。

### 使い方

1. Node.js と [clasp](https://github.com/google/clasp) が使える環境で(セットアップ済みでない場合は下記「事前準備」参照)、`setup/store-config.example.json` をコピーして新しい店舗の設定ファイルを作ります。

   ```bash
   cp setup/store-config.example.json setup/my-restaurant.json
   ```

2. 中身を店舗に合わせて編集します(`storeSlug` は半角英数字とハイフンのみ、`adminPassword` は必ず初期値から変更)。

3. コードを生成します(この時点ではGoogle側には何も作られません)。

   ```bash
   node setup/create-store.js setup/my-restaurant.json
   ```

   `stores/my-restaurant/gas/` に、その店舗用の `Code.gs`(CONFIGだけ差し替え済み)・`index.html`・`admin.html`・`appsscript.json` が生成されます。

4. Google側への反映は次の2通りから選べます。

   - **自動(推奨)**: `--deploy` を付けて再実行すると、新規スプレッドシート作成 → Apps Scriptプロジェクト作成 → コードのpush → ウェブアプリのデプロイまで一括で行います。

     ```bash
     node setup/create-store.js setup/my-restaurant.json --deploy
     ```

     完了すると、スプレッドシートのURL・Apps ScriptエディタのURL・予約フォームURL・管理画面URLが表示されます。

   - **手動**: 生成された `stores/my-restaurant/gas/` の中身を、このREADMEの「セットアップ手順」と同じ手順(新規スプレッドシート作成→Apps Scriptエディタに貼り付け→デプロイ)でコピー&ペーストします。clasp を使わない場合はこちらでもOKです。

5. どちらの方法でも、**発行された予約フォームURLを一度、セットアップに使ったGoogleアカウントで開き、「REVIEW PERMISSIONS」から権限を許可**してください(カレンダー・スプレッドシートへのアクセス許可。店舗ごとに初回1回だけ必要)。

### 事前準備(初めてclaspを使う場合)

```bash
npm install -g @google/clasp
```

`https://script.google.com/home/usersettings` で「Google Apps Script API」を有効化した上で:

```bash
clasp login
```

これは各店舗ではなく、**運用担当者(あなた)のGoogleアカウントで最初に1回だけ**行えば十分です(以降どの店舗を作る際もこのログインを使い回せます)。ただし各店舗の予約フォームを実際に使うカレンダー・スプレッドシートは、`clasp login` したアカウントの Google Drive 上に作られる点に注意してください(別の店舗のGoogleアカウントで管理したい場合は、そのアカウントで `clasp login` し直してから実行します)。

### エンジンを修正したとき

`gas/Code.gs` や `gas/index.html` / `gas/admin.html`(共通エンジン側)にバグ修正や機能追加をしたら、既存の店舗にも反映するには、その店舗の設定ファイルで再度 `create-store.js` を実行してから、その店舗のフォルダで `clasp push` します。

```bash
node setup/create-store.js setup/my-restaurant.json
cd stores/my-restaurant/gas && clasp push -f
```

(`CONFIG` はその店舗の設定ファイルの内容で再生成されるだけなので、既存の予約データや店舗ごとのカスタマイズが上書きされることはありません。ただし `Code.gs` そのものを店舗フォルダ側で直接編集していた場合はその変更が失われるので、共通エンジンへの変更は必ず `gas/Code.gs` 側に行ってください。)
