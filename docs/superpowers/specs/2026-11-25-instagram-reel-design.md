# インスタ用 予約システム紹介リール 設計

## 目的・背景

飲食店オーナーにこの予約システム(GAS版)を「うちにも入れたい」と思ってもらい、**DMで相談してもらう**ための Instagram リールを作る。悩み(営業中の電話・無断キャンセル・満席時の断り)から入り、実際の予約フォーム・管理画面を見せて、DM へ誘導する。

## ゴール / 非ゴール / やってはいけないこと

- ゴール: 約27秒・縦型の MP4 を1本。字幕だけで内容が伝わること。字幕修正 → 再書き出しが手元でできる仕組みを残すこと。
- 非ゴール: BGM・ナレーション(BGM は投稿時にインスタ側で付ける)。複数バリエーションの量産。
- やってはいけないこと:
  - **料金に触れない**(月額・初期費用とも一切出さない)。
  - **実写映像を使わない**(ストック素材含む)。背景はすべて描き起こし。
  - いかにも AI・テンプレ的なつるっとしたモーショングラフィックスにしない。「人が手で作った」感じを優先する。
  - 実在の店名・人名を出さない。

## 制約

- 実行環境はクラウドのコンテナ(Linux)。Chromium + Playwright と ffmpeg(libass 付き)が使える。外部の素材サイトは使わない。
- 予約フォーム `gas/index.html`・管理画面 `gas/admin.html` は GAS のテンプレート(`<? ?>` スクリプトレット、`google.script.run`)なので、そのままではブラウザで開けない。録画用にスタブで動かす必要がある。
- リポジトリのルール(CLAUDE.md)上、`gas/` の本体は録画のために変更しない。

## 作り方の検討(Approaches)

1. **ブラウザで描いて1コマずつ書き出し → ffmpeg で MP4(採用)**
   シーンを HTML/SVG で描き、Playwright で時間を進めながら1コマずつ撮って連番画像にし、ffmpeg で動画化。実物の画面はスタブで動かして同じく撮る。字幕修正 → 再書き出しがコマンド1つ。既存の環境だけで完結する。
2. 動画編集ソフト(CapCut・After Effects 等)で手作業 — 直しのたびに手作業が発生し、この環境では作れないので不採用。
3. Remotion(React の動画フレームワーク)— 可能だが27秒1本には大げさで依存も増えるので不採用。

ユーザーは作り方を一任。1 を採用。

## 決定事項(ユーザーと決めたこと)

- 対象: 飲食店オーナー。行動: **DM で相談**。締めの文言は「『予約』とDMでデモ画面をお送りします」。
- 見た目: **手描きイラスト風(案A)**。線が少しずつ揺れ続ける(数コマごとに線のゆらぎを切り替える)手描きアニメの質感 + 紙のざらつき。サンプルは storyboard ページの「A 手描きイラスト風」。
- 字幕: インスタでよく見る白文字 + 黒フチ。位置・大きさ・傾きはシーンごとに少しずつ変え、揃えすぎない。店主目線の話し言葉。
- 画面シーン: 実物の予約フォーム・管理画面をダミーデータで録画し、手描きの手が持つスマホの中に映す。タップ位置がわかるようにする。
- 店名は架空の「サンプル食堂」、お客様名も架空。

## シーン構成(約27秒)

| # | 秒 | 内容 | 字幕(たたき台) |
|---|----|------|------------------|
| 1 | 0.0–2.5 | 居酒屋カウンターで店の電話が鳴る(プルルル) | 営業中に 電話が鳴りやまない… |
| 2 | 2.5–6.0 | 悩みを1行ずつ畳みかける(厨房・店内の手描き) | ドタキャン・無断キャンセル / 満席なのに電話で断るのがつらい / 予約ノートの書き間違い |
| 3 | 6.0–8.0 | 背景色が変わって転換 | ぜんぶ自動にしませんか? / Googleだけで動く予約システム |
| 4 | 8.0–14.0 | LINE から予約フォーム → 空いている時間だけ選べる(満席はグレー)→ トークに確定メッセージ | LINEからそのまま予約 |
| 5 | 14.0–18.0 | 前日リマインダーメール、キャンセル待ちへの空席通知 | 前日にリマインド自動送信 / キャンセルが出たらキャンセル待ちに自動でお知らせ |
| 6 | 18.0–23.0 | 管理画面: 日別一覧・週間ビュー・集計 | 今日の予約がスマホでひと目で |
| 7 | 23.0–27.0 | のれん/店先の手描き + DM 誘導 | 導入のご相談はDMで / 「予約」とDMでデモ画面をお送りします |

字幕の文言は話し言葉に寄せて実装時に調整してよい(意味は変えない)。

## 出力仕様

- 1080×1920、30fps、H.264(yuv420p)、音声なし、約27秒の MP4。
- 置き場所: `promo/reel/`(シーンの HTML、録画用スタブ、書き出しスクリプト)。書き出した MP4・連番画像はコミットしない(`.gitignore`)。完成 MP4 はユーザーへファイルで渡す。

## 実装者に任せること

- 各シーンのイラストの具体的な構図、カット内の動き、字幕の出し方(ポン出し・ずらし等)。
- 実画面のスタブの作り方(テンプレートの展開方法、ダミーデータの内容)。
- 書き出しの手順(コマ撮りの方法、ffmpeg のオプション)。
- フォントは手元で使える日本語フォント(Google Fonts から取得できるなら Noto Sans JP / Dela Gothic One 等)。
