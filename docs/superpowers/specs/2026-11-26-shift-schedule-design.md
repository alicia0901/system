# シフト表(自動作成つき)設計書

日付: 2026-11-26
状態: 承認待ち

## 1. 目的と背景

飲食店の店長は、今は紙や Excel を使って手でシフトを組んでおり、それに時間がかかっている。困っているのは希望を集めることではなく、**集めた希望をもとに誰をどの枠に入れるかを決める作業**のほう(ユーザー回答)。

そこで、店長がスタッフの出られない日や休み希望、人間関係の条件(「この2人は同じ時間にしない」など)を入力すると、**条件をできるだけ守ったシフト案が自動で作られ、店長はそれを見て手直しするだけ**、という形にする。

既存の飲食店予約システム(GAS)の管理画面に機能として追加する(ユーザーが方式Aを選択)。

## 2. 目標・非目標・アンチゴール

### 目標
- 店長1人で、スタッフ・シフト枠・条件・希望を入力し、ボタン1つで対象期間のシフト案を作れる
- 「一緒にしない」組み合わせを**なるべく避ける**(どうしても人数が足りないときだけ同じ時間に入れて警告を出す)。これは「絶対」ではなく「できれば避けたい」扱い(ユーザー回答)
- シフト枠・担当(ポジション)の形を店ごとに自由に決められる、汎用的な作り(ユーザー回答:「自由に汎用性のあるように」)
- 自動作成のあとに手で直せて、直した結果に対しても警告がその場で更新される
- 印刷して店に貼れる表示がある

### 非目標(今回はやらない)
- スタッフが自分のスマホから希望を出す画面(希望は店長がまとめて入力する。ユーザー回答「②の段階が重い」)
- スタッフ本人用のログインやシフト閲覧ページ
- 予約数に応じて必要人数を自動で増やす連携(将来の拡張候補。データ構造はつなげやすくしておくが、今回は作らない)
- 給与・人件費の計算、勤怠打刻
- 休憩時間の自動割り当て

### アンチゴール(動いても失敗とみなすもの)
- 自動作成が「一緒にしない」を守るために枠を空けたままにする(ユーザーの意図は「人数を満たすのが優先、そのうえで避ける」)
- 自動作成のたびに、店長が手で直した部分まで消されて作り直される
- 設定が複雑すぎて、紙で組むより手間がかかる(担当を使わない店は「ディナー:4人」だけの入力で済むこと)
- 既存の予約機能(予約フォーム・管理画面の予約操作)の動作が変わる

## 3. 制約

- Google Apps Script のみ。外部サーバ・ビルド不要(リポジトリ全体の前提)
- GAS の1回の実行は最大6分。自動作成は余裕を持って **30秒程度以内** に終わること
- `PropertiesService` は1値あたり約9KB、合計約500KB。スタッフや希望のように増えていくデータはプロパティではなくスプレッドシートに保存する
- 「共通エンジン + CONFIG」構造を崩さない。新機能のロジックは `gas/` に置き、`stores/` は生成物として直接編集しない
- `setup/create-store.js` は `gas/` からコピーするファイルを名前で列挙している(`index.html`, `admin.html`, `appsscript.json`, `.claspignore`)。新しいファイルを増やす場合はこのリストに追加する必要がある
- 休業日の判定は CLAUDE.md の規約どおり `getBusinessHoursForDate(dateStr)` を経由する(`CLOSED_WEEKDAYS` などを直接見ない)
- 想定規模: スタッフ 5〜30人程度、対象期間は最大1か月(31日)

## 4. 作り方の選択肢(Approaches)

| 案 | 内容 | 長所 | 短所 |
|---|---|---|---|
| **A. 予約システムの管理画面に追加(採用)** | 同じ GAS プロジェクトにシフト機能を追加。同じパスワードでログイン | ログイン・店舗ごとの設定・他店舗展開の仕組みをそのまま使える。休業日設定を共有でき、将来は予約数と連携できる | 予約システムを使っていない店では使えない。プロジェクトが大きくなる |
| B. 別の GAS プロジェクトとして作る | シフト専用の GAS + スプレッドシート | 予約システムなしで単体で配れる | ログインやデプロイが別になる。予約との連携がしにくい |
| C. ブラウザで開くHTMLファイル1つ | サーバーなし、データはブラウザ保存 | 最も手軽 | データがその端末のブラウザにしか残らず、共有できない |

**ユーザーは A を選択。** 理由:このリポジトリはもともと飲食店向けで、店舗ごとに展開する仕組みもすでにあるので、それに乗せるのが一番無駄がない。予約データとつなげられる点も、他の案にはない強み。

## 5. ユーザーが決めたこと

- 「出られない」は日単位に加え、枠単位(「ランチは無理、ディナーなら出られる」)と、毎週くり返す定期条件(「平日のランチはいつも無理」)の両方に対応する
- 公平さは、スタッフごとの「週◯日くらい入りたい」(週の目安日数)に近づける形にする。全員の日数をそろえるのではない
- 使うのは店長だけ。希望は店長が入力する
- シフト枠と担当の形は店ごとに自由に設定できる
- 「一緒にしない」は「できれば避けたい」扱い。人数を満たすことを優先し、守れないときは一緒に入れたうえで警告を出す
- 方式は A(既存の管理画面に追加)

## 6. 設計

### 6.1 画面の置き場所(私の判断)

管理画面(`admin.html`)はすでに約1800行あり、シフト表は横に広い表を扱うので、**別ページ `?page=shift`(新ファイル `gas/shift.html`)** にする。

- 管理画面の上部ボタン列に「シフト表」ボタンを追加し、`?page=shift` へ移動する
- ログインは管理画面と同じ `adminLogin` / `isValidAdminToken`(同じパスワード)。`sessionStorage` に保存したトークンが引き継げればそのまま入り、使えない環境ならシフト画面でもう一度パスワードを入れる
- サーバ側のロジックは **新ファイル `gas/Shift.gs`** に置く(GAS では複数の .gs ファイルが同じ名前空間を共有するので、`Code.gs` の関数や定数をそのまま使える)。`Code.gs` 側の変更は `doGet` の振り分け追加だけにする
- `setup/create-store.js` のコピー対象と `gas/.claspignore` の許可リストに `Shift.gs` と `shift.html` を追加する

### 6.2 シフト画面の構成

上部のタブで4つの画面を切り替える:

```
[ シフト表 ] [ スタッフ ] [ 希望・休み ] [ 枠と条件 ]
```

1. **シフト表**: 期間を選び、「自動作成」ボタンでシフト案を作る。表を見て手直し・保存・印刷する
2. **スタッフ**: スタッフの追加・編集
3. **希望・休み**: 期間内の、スタッフごとの出られない日・休みたい日・出たい日をカレンダー形式で入力する。日ごとに「終日」か「特定の枠だけ(例:ランチだけ無理)」かを選べる(ユーザー回答)。スタッフ画面では「いつも出られない曜日・枠」(例:平日のランチ、毎週水曜)を登録でき、毎回入れ直さなくてよい(ユーザー回答)
4. **枠と条件**: シフト枠、必要人数、担当、「一緒にしない」などの組み合わせ条件

シフト表の見た目(スマホでは横スクロール):

```
            11/1(土)        11/2(日)        11/3(月) 定休
ランチ      ホール: 田中    ホール: 佐藤
10-15       キッチン: 鈴木  キッチン: 鈴木
ディナー    ホール: 田中    ホール: 高橋 ⚠
17-23       ホール: 山本    ホール: 伊藤 ⚠
            キッチン: 中村  キッチン: 不足 ⚠
---
⚠ 11/2 ディナー: 高橋さんと伊藤さんが同じ時間(できれば避けたい組み合わせ)
⚠ 11/2 ディナー: キッチンが1人不足
```

- セルをタップすると、その枠・担当に入れられるスタッフの一覧が出て、入れ替えや追加・外すことができる。一覧では、出られない人をグレー表示し、入れると条件違反になる人には理由を出す
- 手で変更した割り当てには「固定」の印が付く。**もう一度自動作成しても固定した割り当ては変えない**(私の判断。アンチゴール「手直しが消える」を防ぐため)。固定は個別に外せる。全部消して作り直すボタンも別に置く
- 「この人をこの枠から外した」も固定として記録する(除外の固定)。再作成でその人をその枠に戻さない(私の判断。同じ理由)
- 自動作成は**画面上の今の割り当て(未保存の手直しを含む)**をサーバに送り、その中の固定だけを残して残りを作り直す。先に保存しなくてもよい(私の判断)
- 手直しでは絶対条件(出られない日・担当外・週の上限)を破る割り当ても**店長の判断で入れられる**。ただし赤い警告を出す。店長が本人と話して「その日は出られる」と決めることがあるため(私の判断)。例外として、同じ人を時間が重なる2枠に入れることは物理的に無理なのでできない。自動作成は絶対条件を破る割り当てを自分からは作らないが、店長が固定したものはそのまま受け入れる
- 特別な日の枠(私の判断): 営業時間が変わった日もその曜日の枠をそのまま出す(仕込み・片付けで営業時間の前後に人がいるのは普通なので、営業時間に合わせて枠を削らない)。普段は定休日の曜日に臨時営業する日は、営業時間と時間が重なる枠をすべて出す。どの日でも、シフト表上でその日だけ枠を消したり戻したりできる
- 警告は表の下にまとめて出し、該当するセルにも ⚠ を付ける。手直しのたびに画面上で計算し直す
- 下にスタッフごとの集計(期間内の出勤日数・時間、上限との比較)を出す
- 「印刷」ボタンで、操作ボタンを隠した白黒でも読める表を印刷用のCSSで出す

### 6.3 データモデル

**シフト枠と条件の設定**は、件数が少ないので `PropertiesService` のキー `SHIFT_SETTINGS`(JSON)に保存する。

```js
{
  positions: ['ホール', 'キッチン'],   // 空配列なら「担当なし」の店
  slots: [
    {
      id: 's1', name: 'ランチ', start: '10:00', end: '15:00',
      weekdays: [0,2,3,4,5,6],         // この枠を使う曜日
      required: { 'ホール': 1, 'キッチン': 1 }  // 担当なしの店は { '': 3 } の形
    },
    ...
  ],
  pairRules: [
    { a: 'staffId1', b: 'staffId2', type: 'avoid' },   // できれば同じ時間にしない
  ],
  minVeteranPerSlot: 1   // 各枠に「ベテラン」を最低何人入れたいか(0なら無効)
}
```

**スタッフ・希望・確定シフト**は、件数が増え、店長が Excel 感覚でシートを直接見たくなる可能性もあるので、予約と同じスプレッドシートに専用シートを作って保存する(シートがなければ自動作成。`getOrCreateSheet` と同じやり方)。

| シート名 | 列 |
|---|---|
| `シフト_スタッフ` | スタッフID, 名前, できる担当(カンマ区切り), ベテラン(TRUE/FALSE), 週の目安日数, 週の上限日数, 週の上限時間, 在籍(TRUE/FALSE), メモ |
| `シフト_希望` | 日付, スタッフID, 枠ID(空なら終日), 種類(`出られない` / `できれば休み` / `出たい`), メモ |
| `シフト_定期条件` | スタッフID, 曜日(カンマ区切り), 枠ID(空なら終日), 種類(`出られない` / `できれば休み`), メモ … 毎週くり返す条件 |
| `シフト_割り当て` | 日付, 枠ID, 担当, スタッフID, 種類(`割り当て` / `除外`), 固定(TRUE/FALSE), 更新日時 |
| `シフト_日別枠` | 日付, 枠ID, 状態(`なし` / `あり`) … その日だけ枠を消した・戻した記録 |

- 同じ日・枠について、その日だけの希望と毎週の定期条件がぶつかったら**その日だけの希望を優先**する(例:「水曜はいつも休み」でも、11/12(水)に「出たい」と入れればその日は入れる)(私の判断)
- スタッフは**削除せず「在籍 FALSE」にする**(過去のシフトに名前を残すため)
- スタッフIDは追加時に作る短い文字列(名前を変えても条件が崩れないようにするため)
- 保存の単位は「期間」。保存すると、その期間の割り当て行を消してから書き直す(`LockService` で排他する)

### 6.4 条件の強さ

| 条件 | 強さ | 守れないとき |
|---|---|---|
| 出られない日・枠(その日だけの希望 + 毎週の定期条件) | 絶対 | 割り当てない(枠が不足しても入れない) |
| 休業日(`getBusinessHoursForDate` が休業) | 絶対 | その日は枠を出さない |
| できる担当以外には入れない | 絶対 | 割り当てない |
| 同じ人を時間が重なる2枠に入れない | 絶対 | 割り当てない |
| 週の上限日数・上限時間 | 絶対 | 割り当てない(私の判断。法的な労働時間や扶養の範囲が絡むため) |
| 必要人数を満たす | 強い希望 | 不足として警告 |
| できれば休み | 希望 | 入れたら警告 |
| 一緒にしない(avoid) | 希望 | 一緒に入れたら警告 |
| ベテランを最低◯人 | 希望 | 足りなければ警告 |
| 出たい | 希望(加点) | 警告なし |
| 週の目安日数に近づける(公平さ) | 希望 | 警告なし。集計で目安より多い・少ない人がわかるように色を付ける |

優先順位は **必要人数 > 一緒にしない > できれば休み > ベテラン > 公平さ(目安日数) > 出たい**(私の判断)。公平さは「目安日数との差」の大きさで罰点を付ける(ユーザー回答:目安に近づける)。目安日数が空のスタッフは、上限の範囲内でほかの人と同じくらいの割合になるよう扱う(私の判断)。「一緒にしない」はユーザーの関心の中心なので、休み希望より上に置いた。ただし必要人数よりは下に置く(ユーザー回答:人数を満たすのが優先)。

「同じ時間」の定義: **同じ日で、2人の入っている枠の時間が1分でも重なること**。たとえば「ランチ 10-15」の人と「通し 10-23」の人は同じ時間とみなす。

### 6.5 自動作成の仕組み

点数方式にする。各条件の違反に重みを付けた**罰点の合計が小さいほど良い案**とし、上の優先順位どおり、上位の違反1件が下位の違反を何件重ねても上回るように重みを付ける。

1. 固定された割り当てはそのまま置く
2. **最初の案(貪欲法)**: 足りない人数の多い枠、入れられる人の少ない枠から順に、その時点で罰点が一番増えない人を入れていく。絶対条件を破る人は候補にしない
3. **改善**: 時間の上限(目安20秒)まで、ランダムに「1人を入れ替える」「2人の枠を交換する」を試し、罰点が下がれば採用する(局所探索。悪化も低い確率で受け入れる焼きなまし法でもよい。選ぶのは実装者)
4. 結果と警告の一覧を返す。この時点ではシートに保存しない。店長が画面で確認して「保存」を押したときに保存する

自動作成は `Shift.gs` 側(サーバ)で動かす。警告の計算は画面側でも手直しのたびに行うので、**罰点・警告を計算する関数は同じ考え方でサーバ側と画面側の両方に置く**。共通化できるなら共通化するのが望ましい(例:`shift.html` に読み込むスクリプトをサーバからテンプレートで出力する)。どこまで共通化するかは実装者に任せる。

### 6.6 サーバ API(`Shift.gs`)

すべて `token` を受け取り、`isValidAdminToken` が失敗したら既存と同じ形 `{ success: false, authError: true, message }` を返す。

- `getShiftBootstrap(token, fromDate, toDate)`: 設定・在籍スタッフ・期間内の希望・期間内の割り当て・期間内の各日の営業状況(`getBusinessHoursForDate`)をまとめて返す
- `saveShiftSettings(token, settings)`: 枠・担当・組み合わせ条件の検証と保存
- `saveStaff(token, staff)` / `setStaffActive(token, staffId, active)`
- `saveRequests(token, fromDate, toDate, requests)`: 期間内の希望を丸ごと置き換える
- `generateShift(token, fromDate, toDate, currentAssignments)`: 自動作成。`currentAssignments` のうち固定(割り当て・除外)だけを残し、残りを作る。結果(割り当て + 警告 + 集計)を返すだけで、保存はしない
- 週の上限は、期間の端の週(例: 期間が土曜始まりなら前の月〜金)について**期間外の保存済み割り当ても数える**。`getShiftBootstrap` と `generateShift` は期間の前後の週にはみ出した分の保存済み割り当てを読み込み、動かさない前提で扱う(私の判断。絶対条件が期間の境目で黙って破られないようにするため)
- `saveAssignments(token, fromDate, toDate, assignments)`: 期間内の割り当てを置き換えて保存する

入力の検証は既存の `updateCoursesAdmin` などと同じく、日本語のエラーメッセージで `{ success: false, message }` を返す。

### 6.7 既存コードへの影響

- `Code.gs`: `doGet` に `page === 'shift'` の振り分けを追加するだけ。CONFIG ブロックは変更しない
- `admin.html`: 上部のボタン列に「シフト表」ボタンを1つ追加
- `setup/create-store.js` / `gas/.claspignore`: コピー対象・許可リストに `Shift.gs` と `shift.html` を追加
- `README.md` / `CLAUDE.md`: シフト機能の説明を追記
- 予約関連のシート・関数・プロパティには一切手を入れない

- 局所探索の手法の詳細(単純な山登りか焼きなましか、試行回数)
- 画面のデザイン細部。既存の `admin.html` の見た目(CSS 変数・ボタン・アイコン)に合わせる

- スタッフIDの形式

## 8. 確認方法

このリポジトリにはテストの仕組みがない。自動作成の中核(罰点計算・貪欲法・局所探索)は GAS の API に依存しない純粋な関数として書き、Node で直接動かせる簡単な確認スクリプトで次を確かめる:

- 出られない日の人が割り当てられない(終日・枠単位・毎週の定期条件のいずれでも)
- 週の目安日数が違う2人(週1日と週4日)で、出勤日数がそれぞれの目安に近くなる
- 人数が足りる状況では「一緒にしない」2人が同じ時間に入らない
- 人数が足りない状況では、枠を空けずに2人を一緒に入れ、警告を出す
- 固定した割り当てが自動作成で変わらない
- 時間が重なる枠(ランチと通し)が「同じ時間」と判定される
- 30人・31日・1日3枠の規模で、20秒程度で終わる
